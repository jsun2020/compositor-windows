# Phase 3.5a: Open and Save macOS Compositor 1.2.6 Projects Without Loss - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every project the user's Mac app (Compositor 1.2.6, format version 9) saves opens in the Windows port, renders everything the port can already draw, says plainly what it cannot draw yet, and re-saves with nothing lost.

**Architecture:** The manifest types gain the v8/v9 fields and a catch-all for keys this build does not know, so a round trip never drops data. The eleven new blend-mode strings and six new adjustment kinds are parsed, validated exactly as the Mac validates them, and composited as Normal / identity until Phase 3.5b draws them. Folder opacity (v8) is drawn now, because it is a one-function change in the render plan that both compositors already consume. Saved guides (v8) move with Canvas Size, Crop, Image Size and Flip, and are drawn. A notice lists what a project contains that this build does not draw.

**Tech Stack:** Rust (`engine`, `engine-wasm`), serde / serde_json, TypeScript + React + zustand (`app`), WebGL2, vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-20-windows-port-design.md`, section 2 (file compatibility tracks the Mac's current format; never silently lose data) and section 3, Phase 3.5.

**Research this plan argues from:** `docs/superpowers/research/mac-1.2.6-format-delta.md` (every Mac claim below cites it as "R <section>").

**Out of scope (Phase 3.5b):** actually drawing the new blend modes, the new adjustment kinds and layer effects; panels for Black & White and Color Balance; the 1.2.6 Grain and Add Noise kernel changes; rescaling effects through Image Size.

## Global Constraints

- ASCII only in every source file, test, doc and commit message.
- Read every format version 1 to 9. Always WRITE version 9, as the Mac 1.2.6 does whatever the content (R 1.1).
- Validation mirrors Mac 1.2.6 `ProjectStore.validate` (R 1, R 2): a file the Mac accepts must open here, and a file this port writes must pass the Mac's validation.
- Never silently lose data. Every key read from a manifest, at the manifest level and at the layer-record level, is written back on save unless a rule in this plan names it as dropped. The only such rules: `shape` and `text` are dropped when that layer's pixels are replaced (R 2.2, R 2.3).
- JSON written for the Mac follows synthesized Swift `Codable` (R 0): optionals are omitted when absent, never `null`; UUIDs are uppercase; enums use their exact raw values; typed floats are written through `mac_number` (whole numbers as `16`, not `16.0`); keys come out sorted.
- The object form of Hue/Saturation maps stays on the wasm bridge; the array form is file-only (unchanged from Phase 3).
- Tests: for EVERY assertion you write, be able to name the production change that makes it fail. Prefer asymmetric fixtures (not square, not default-valued, a starting state that is not the asserted state). Prove the assertions that close a behaviour by introducing the bug, watching the test fail, and reverting.
- E2E: prove commits with `undoDepth` against a baseline, never `canUndo`; never pass a message as a matcher's second argument; locate form fields by role plus name (`getByRole("spinbutton", { name, exact: true })`), because accessible names collide with dialogs, sliders and chips.
- Panels are `position: fixed` and never enter layout flow (several specs pin the window height and compare pixels).
- After any change under `engine/src` or `engine-wasm`, run `pnpm wasm:dev` before `pnpm build` and `pnpm e2e`. `wasm:dev` is unoptimized: never quote a timing from it.
- Run every suite in the FOREGROUND. Commit with an explicit pathspec (`git commit -- <paths>`); `git add` new files first. End every commit message with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.
- Baseline before Task 1: `cargo test -p compositor-engine` 203 across 34 binaries, vitest 111, build clean, e2e 75.

```rust
/// A layer's drawn opacity: its own times every enclosing folder's, up to 64 levels
/// (LayerOpacity.effective, LayerGroups.swift:49-64). Per-descendant multiplication, never group
/// compositing: folders are pass-through, so this matches the Mac rather than Photoshop. Every
/// draw in the plan goes through here (plain layers, stack bases and children, mask sources,
/// adjustment strength), which is what makes a clipped child in a dimmed folder dim twice, as
/// the Mac's LiveMaskRenderer does.
fn effective_opacity(by_id: &HashMap<Uuid, &Layer>, layer: &Layer) -> f64 {
    let mut opacity = layer.opacity.clamp(0.0, 1.0);
    let mut parent = layer.parent_id;
    let mut depth = 0;
    while let Some(pid) = parent {
        if depth >= MAX_NESTING { break; }
        let Some(folder) = by_id.get(&pid) else { break };
        opacity *= folder.opacity.clamp(0.0, 1.0);
        parent = folder.parent_id;
        depth += 1;
    }
    opacity
}
```
